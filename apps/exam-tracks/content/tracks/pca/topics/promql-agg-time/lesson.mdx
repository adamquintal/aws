## Squashing a window into one number

The previous topic's functions (`rate`, `deriv` and so on) measure *change*. The `_over_time` family **summarises** a window instead. Each one takes a range vector and returns one value per series, keeping the series' labels:

| Function | Result per series |
|---|---|
| `avg_over_time(v[d])` | average of the samples in the window |
| `min_over_time(v[d])` / `max_over_time(v[d])` | lowest / highest sample |
| `sum_over_time(v[d])` | sum of the samples |
| `count_over_time(v[d])` | number of samples |
| `quantile_over_time(φ, v[d])` | the φ-quantile (0 ≤ φ ≤ 1) of the samples |
| `stddev_over_time` / `stdvar_over_time` | population standard deviation / variance |
| `last_over_time(v[d])` | the most recent sample |
| `present_over_time(v[d])` | 1 for any series that had a sample in the window |

These work on **gauges** and **counters** alike, because they don't assume anything about direction. Some examples:

```promql
max_over_time(node_load1[1h])                  # worst 1-minute load in the last hour
avg_over_time(process_resident_memory_bytes[10m])
quantile_over_time(0.95, node_load1[1d])       # 95th percentile of load over a day
count_over_time(up[1h])                        # how many scrapes happened in the last hour
```

One detail from the docs: **every sample in the window counts equally**, even if samples aren't evenly spaced.

## Detecting missing data

- `absent(v)` returns a single series with value 1 if the instant vector you pass has **no** elements, and nothing otherwise.
- `absent_over_time(v[d])` does the same for a whole window: 1 if there were no samples at all.

```promql
absent_over_time(nonexistent{job="myjob"}[1h])   # => {job="myjob"} 1
```

Both try to derive sensible labels from the selector, which makes them handy in alerts like "this job has reported nothing for an hour".

## Subqueries: a range from any expression

What if you want the **highest request rate** in the last hour? `rate()` returns an instant vector, but `max_over_time` needs a range vector. A **subquery** bridges the gap:

```promql
max_over_time( rate(http_requests_total[5m])[1h:] )
```

Syntax: `<instant_query>[<range>:<resolution>]`

- `<range>` is how far back to go (here 1h).
- `<resolution>` is the step between evaluations. It's optional, and when omitted the **global evaluation interval** is used.
- The result is a **range vector**, so it can be fed to any `_over_time` function.

From the official examples, here's the 5-minute rate for the past 30 minutes at 1-minute resolution:

```promql
rate(http_requests_total[5m])[30m:1m]
```

The docs add a caution: **using subqueries unnecessarily is unwise.** They're expensive. If you need the same subquery often, a recording rule that stores the inner expression is usually better.

## The colon matters

| You write | What it is |
|---|---|
| `x[1h]` | a range vector selector (only valid directly on a selector) |
| `rate(x[5m])[1h:]` | a subquery over an expression |
| `rate(x[5m])[1h]` | **invalid**, because an expression needs the colon form |
