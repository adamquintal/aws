## The shape of a /metrics page

When Prometheus scrapes a target, it makes an HTTP request, usually to `/metrics`, and reads back plain text. Here's part of the official example from the docs:

```text
# HELP http_requests_total The total number of HTTP requests.
# TYPE http_requests_total counter
http_requests_total{method="post",code="200"} 1027 1395066363000
http_requests_total{method="post",code="400"}    3 1395066363000

# Minimalistic line:
metric_without_timestamp_and_labels 12.47
```

### Sample lines

Each sample line has up to three parts, separated by whitespace:

```text
metric_name{label="value",...}   value   [timestamp]
```

- **Name and labels**: the labels are optional, as the minimalistic line shows.
- **Value**: a float. `NaN`, `+Inf` and `-Inf` are valid too.
- **Timestamp**: optional, an int64 in **milliseconds** since 1970-01-01 UTC. Most targets leave it out and let Prometheus use the scrape time.

### HELP and TYPE

Lines starting with `#` are comments, with two exceptions:

- `# HELP <name> <docstring>` describes the metric. Only one per metric.
- `# TYPE <name> <type>` declares the type: `counter`, `gauge`, `histogram`, `summary` or `untyped`. Only one per metric, and it must come **before** that metric's first sample. With no TYPE line, the metric is **untyped**.

### Grouping rules

- All lines for one metric must appear together as one group, with HELP and TYPE first.
- Each combination of metric name and labels may appear only once. Duplicates make ingestion behaviour undefined.
- Backslash, double-quote and newline inside label values must be escaped as `\\`, `\"` and `\n`.

## Histograms and summaries in text

These types expand into several lines:

```text
# TYPE http_request_duration_seconds histogram
http_request_duration_seconds_bucket{le="0.05"} 24054
http_request_duration_seconds_bucket{le="0.1"} 33444
http_request_duration_seconds_bucket{le="+Inf"} 144320
http_request_duration_seconds_sum 53423
http_request_duration_seconds_count 144320
```

- Histogram: one `_bucket` line per bucket, with the upper bound in `le`, in increasing order. There **must** be a `le="+Inf"` bucket, and its value **must** equal `_count`.
- Summary: one line per quantile, with a `quantile` label, plus `_sum` and `_count`.

## Formats and Content-Types

| Format | Content-Type | Notes |
|---|---|---|
| Prometheus text | `text/plain; version=0.0.4` | Human-readable, the classic format |
| OpenMetrics text | `application/openmetrics-text; version=1.0.0` | Standardised format built on the Prometheus text format. Must end with `# EOF`. Adds types such as Info, StateSet and GaugeHistogram, plus exemplars and unit metadata. |
| Protobuf | `application/vnd.google.protobuf; proto=io.prometheus.client.MetricFamily; encoding=delimited` | Binary, not human-readable, needed for native histograms |

**OpenMetrics** grew out of the Prometheus text format as an effort to standardise metric exposition. Prometheus can scrape it, and it supports **exemplars**, which can attach a trace ID to a sample. That turns out to be a useful bridge to tracing later on.
