## What a client library does

To monitor your own service, you add **instrumentation** to its code with a client library in the same language. The library:

1. implements the four metric types (counter, gauge, histogram, summary),
2. keeps their current values in memory in a **registry**, and
3. serves them over HTTP. When Prometheus scrapes, the library sends **the current state of all tracked metrics**.

### Official and third-party libraries

| Official (maintained by Prometheus) | Third-party examples |
|---|---|
| Go, Java or Scala, Node.js, Python, Ruby, Rust | C, C++, .NET/C#, PHP, Erlang, Elixir, Haskell, Lua, Perl, Swift… |

No library for your language, or you want zero dependencies? The text exposition format is simple enough to write by hand.

## A minimal Go example

From the official Go guide, this serves the standard Go and process metrics on `:2112/metrics`:

```go
reg := prometheus.NewRegistry()
reg.MustRegister(
    collectors.NewGoCollector(),
    collectors.NewProcessCollector(collectors.ProcessCollectorOpts{}),
)
http.Handle("/metrics", promhttp.HandlerFor(reg, promhttp.HandlerOpts{}))
http.ListenAndServe(":2112", nil)
```

Adding your own counter is a few more lines, and the guide's example then exposes:

```text
# HELP myapp_processed_ops_total The total number of processed events
# TYPE myapp_processed_ops_total counter
myapp_processed_ops_total 5
```

## The standard API (across languages)

The "writing client libraries" guidelines keep libraries consistent:

| Type | Methods |
|---|---|
| **Counter** | `inc()`, `inc(v)` where **v must be ≥ 0**. Starts at 0 and never decreases (a restart resets it). |
| **Gauge** | `inc()`, `dec()`, `set(v)`, and usually `set_to_current_time()`. Helpers for in-progress tracking and timing. |
| **Summary** | `observe(v)`, plus a way to time code **in seconds**. By default only `_count` and `_sum`, no quantiles. |
| **Histogram** | `observe(v)`, plus timing in seconds. Buckets are chosen up front and can't change after creation. |

Every metric **must have a help string**. The name can often be given in three parts, `namespace_subsystem_name`.

### Labels

You declare label *names* when you create the metric, then get a **child** for specific label *values*:

```text
requests.labels("GET", "200").inc()
```

Libraries reserve `le` (histogram buckets) and `quantile` (summary quantiles), so you can't use those as your own label names. Metrics without labels are initialised to 0, so they're never missing.

## Free metrics: process and runtime

Libraries register standard metrics automatically:

| Metric | Meaning |
|---|---|
| `process_cpu_seconds_total` | CPU time used (a counter) |
| `process_resident_memory_bytes` | Resident memory (a gauge) |
| `process_open_fds` / `process_max_fds` | File descriptors |
| `process_start_time_seconds` | Start time as a Unix timestamp |

Plus runtime metrics with a language prefix, such as `go_goroutines` and `go_gc_duration_seconds`.
