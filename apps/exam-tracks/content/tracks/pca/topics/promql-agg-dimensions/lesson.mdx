## Across series, not across time

The previous topic aggregated **over time**, collapsing each series' window into one value. This topic aggregates **over dimensions**: at a single moment, many series are combined into fewer by grouping on labels.

| | Works across | Input | Example |
|---|---|---|---|
| `_over_time` functions | time, within one series | range vector | `max_over_time(x[1h])` |
| aggregation operators | series, at one instant | instant vector | `max(x)` |

## The operators

| Operator | Result |
|---|---|
| `sum`, `avg`, `min`, `max` | total, mean, smallest, largest |
| `count` | number of series |
| `group` | 1 for each group (useful for "which label values exist?") |
| `stddev`, `stdvar` | population standard deviation / variance |
| `quantile(φ, v)` | φ-quantile across the series, such as `quantile(0.5, …)` for the median |
| `topk(k, v)` / `bottomk(k, v)` | the k largest / smallest series |
| `count_values("label", v)` | how many series have each distinct value |

## by and without

```promql
sum without (instance) (memory_consumption_bytes)
sum by (application, group) (memory_consumption_bytes)
```

If `memory_consumption_bytes` fans out by `application`, `instance` and `group`, these two are **equivalent** (an example from the docs):

- **`without (instance)`** removes `instance` and keeps everything else.
- **`by (application, group)`** keeps only those two labels and drops the rest.
- With **neither**, everything collapses into one series with no labels: `sum(memory_consumption_bytes)`.

The clause can go before or after the expression:

```promql
sum by (job) (rate(http_requests_total[5m]))
sum(rate(http_requests_total[5m])) by (job)
```

The recording-rules guide recommends **`without`** with the labels you're aggregating away, so other useful labels (such as `job`) are kept automatically.

## Rate first, then aggregate

This is the real query pattern you'll write most:

```promql
sum by (job) (
  rate(http_requests_total[5m])
)
```

Take the per-series `rate()` first, so each series' counter resets are handled, and *then* add the rates together.

## topk and bottomk keep original series

Unlike `sum` or `avg`, `topk` and `bottomk` don't compute a new value. They **return a subset of the input series, with their original labels**:

```promql
topk(5, memory_consumption_bytes)                              # the 5 biggest memory users
topk(3, sum by (app, proc) (rate(instance_cpu_time_ns[5m])))   # top 3 CPU users per app/proc
```

With `by` or `without`, the labels only define the groups. You get the top k *within each group*.

## Counting things

```promql
count by (app) (instance_cpu_time_ns)        # running instances per application
count_values("version", build_version)       # how many binaries run each build version
```

`count_values` creates one output series per **distinct sample value** and puts that value in the label you name.
