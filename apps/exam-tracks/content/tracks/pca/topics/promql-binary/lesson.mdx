## Arithmetic

`+  -  *  /  %  ^` work between scalars, between a vector and a scalar (applied to every sample), and between two vectors (applied to each **matched pair**).

```promql
(instance_memory_limit_bytes - instance_memory_usage_bytes) / 1024 / 1024   # unused memory in MiB
```

When vectors are involved, **the metric name is dropped** from the result, because "limit minus usage" isn't either original metric any more.

## Comparisons filter by default

`==  !=  >  <  >=  <=`

```promql
up == 0                        # only the targets that are down
node_load1 > 4                 # only the series above 4
```

A comparison against a vector **filters**: series where it's false are removed, and survivors keep their original values. Add **`bool`** to get a 0 or 1 for every series instead:

```promql
up == bool 0                   # 1 for down targets, 0 for healthy ones
```

`bool` also drops the metric name. Between two **scalars**, `bool` is required (`2 > bool 1` returns 1).

## Set operators: and, or, unless

These work only between instant vectors, and match on **exact label sets**:

| Expression | Result |
|---|---|
| `a and b` | series in `a` that have a matching label set in `b` (values from `a`) |
| `a or b` | all of `a`, plus series from `b` with no match in `a` |
| `a unless b` | series in `a` that have **no** match in `b` |

## Vector matching

When both sides are vectors, each series on the left looks for a partner on the right. By default, partners must have **exactly the same labels**. Unmatched series are dropped.

Using the docs' example data:

```text
method_code:http_errors:rate5m{method="get", code="500"}  24
method_code:http_errors:rate5m{method="get", code="404"}  30
method_code:http_errors:rate5m{method="put", code="501"}  3
method_code:http_errors:rate5m{method="post", code="500"} 6
method_code:http_errors:rate5m{method="post", code="404"} 21

method:http_requests:rate5m{method="get"}  600
method:http_requests:rate5m{method="del"}  34
method:http_requests:rate5m{method="post"} 120
```

### One-to-one with ignoring / on

```promql
method_code:http_errors:rate5m{code="500"} / ignoring(code) method:http_requests:rate5m
```

```text
{method="get"}  0.04     # 24 / 600
{method="post"} 0.05     #  6 / 120
```

- `ignoring(code)` compares labels **except** `code`. `on(method)` would compare **only** `method`, with the same effect here.
- `put` and `del` have no partner, so they're dropped.

### Many-to-one with group_left

Without the `{code="500"}` filter, the left side has **several** series per `method` (one per code), all wanting the same right-hand partner. That has to be allowed explicitly:

```promql
method_code:http_errors:rate5m / ignoring(code) group_left method:http_requests:rate5m
```

```text
{method="get", code="500"}  0.04    # 24 / 600
{method="get", code="404"}  0.05    # 30 / 600
{method="post", code="500"} 0.05    #  6 / 120
{method="post", code="404"} 0.175   # 21 / 120
```

- **`group_left`**: the **left** side has higher cardinality (many-to-one).
- **`group_right`**: the **right** side has higher cardinality (one-to-many).
- You can list extra labels to copy from the "one" side, as in `group_left(team)`.

The docs advise care: often a well-chosen `ignoring(...)` is enough.

## Precedence (highest first)

1. `^` (right-associative: `2 ^ 3 ^ 2` = `2 ^ (3 ^ 2)`)
2. `*  /  %  atan2`
3. `+  -`
4. `==  !=  <=  <  >=  >`
5. `and  unless`
6. `or`

Everything except `^` is left-associative: `2 * 3 % 2` = `(2 * 3) % 2`.

## Ratios: divide sums, don't average ratios

To get an error ratio across many instances, **sum the numerator and the denominator first, then divide**:

```promql
sum without (instance) (rate(http_errors_total[5m]))
/
sum without (instance) (rate(http_requests_total[5m]))
```

The recording rules guide warns that averaging ratios, or averaging averages, isn't statistically valid.
